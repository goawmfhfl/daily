# HSK 독해 연습 — 기획

중국어 페이지의 세 번째 탭 **독해**. AI가 HSK 6급 독해 빈칸 채우기 세트를 만들고, 풀면 바로 채점·해설하고, 틀린 빈칸은 오답노트에 쌓아 간격을 두고 다시 풀게 한다.

> 형식 메모: 초안의 "독해 1부분"(지문 1개 + 빈칸 여러 개 + 보기 4개)은 현행 HSK 6급 시험지에서는 阅读 第二部分 选词填空에 해당한다. 앱 안에서는 `part = 1`(빈칸 채우기)로 두고, 화면에는 "빈칸 채우기"로 표기한다. 이후 문장 고르기·독해 이해 등은 `part` 값만 늘려 같은 테이블과 화면 골격에 붙인다.

## 1. 사용자 흐름

1. **독해 탭 첫 화면**
   - 급수: 6급(이번 범위). 다른 급수는 "준비 중"으로 보이게만 둔다.
   - 주제: 랜덤(기본) 또는 칩으로 고르기. 일상·직장·과학·문화·역사·사회·건강·환경·경제·인물.
   - "문제 풀기" 버튼과 함께 준비된 세트 수(풀), 푼 세트 수, 평균 정답률, 오늘 복습할 오답 수를 보여 준다.
2. **풀이**
   - 지문 안 빈칸은 번호 칩 `1 ____`으로 표시하고, 보기를 고르면 그 자리에 고른 단어가 들어간다.
   - 지문 아래에는 빈칸별 보기 4개(A–D)가 있다. 지문의 빈칸 칩을 누르면 해당 문항으로 이동한다.
   - 경과 시간을 작게 보여 준다(실제 시험 감각 유지용, 제한은 없음).
   - 5문항을 모두 고르면 "제출"이 켜진다.
3. **채점·해설**
   - 점수(4/5)와 걸린 시간.
   - 지문의 빈칸은 정답이면 초록, 오답이면 고른 단어에 취소선을 긋고 정답을 함께 표시한다.
   - 문항별로 정답, 왜 정답인지(호응·논리 근거), 보기 4개 각각의 뜻과 틀린 이유를 보여 준다.
   - 보기 단어마다 "단어장에 추가"가 있다. 기존 단어장 AI 카드 생성을 그대로 쓰고, 지문 문장을 문맥으로 넘긴다.
   - "지문 해석 보기"(한국어 번역), "정답이 이상해요" 신고, "다음 세트".
4. **오답노트**
   - 제출할 때 틀린 빈칸이 자동으로 쌓인다(세트별로 묶음).
   - **다시 풀기**: 그 세트를 다시 열되, 틀렸던 빈칸만 풀고 나머지는 정답으로 채워 둔다.
     - 맞히면 다음 복습이 내일 → 3일 → 1주 뒤로 미뤄지고, 세 번 맞히면 "해결".
     - 틀리면 처음 단계로 돌아가 내일 다시 나온다.
   - **비슷한 문제 만들기**: 틀린 빈칸의 정답 단어를 꼭 쓰는 새 세트를 같은 주제로 생성한다.

## 2. 문제 생성 (AI)

### 입력과 출력
- 입력: 급수, 주제(없으면 AI가 랜덤으로 고름), 빈칸 수(5), 지문 길이(6급 350~500자), 꼭 쓸 단어(비슷한 문제용).
- 출력(Structured Outputs, strict):

```json
{
  "topic": "환경",
  "title": "城市里的屋顶花园",
  "passage": "… {{1}} … {{2}} …",
  "translation_ko": "지문 전체 한국어 번역",
  "blanks": [
    {
      "no": 1,
      "options": ["繁荣", "繁华", "繁忙", "繁殖"],
      "answer": 1,
      "explanation": "왜 정답인지 (호응·문맥 근거, 한국어)",
      "option_notes": ["보기별 뜻과 틀린/맞는 이유 (한국어)", "…", "…", "…"]
    }
  ]
}
```

### 출제 원칙 (프롬프트)
- 정답은 정확히 하나다. 나머지 보기는 문법이나 호응, 의미, 논리 중 하나 이상에서 분명히 틀려야 한다.
- 한 빈칸의 보기 4개는 같은 품사, 같은 글자 수(2자 단어끼리, 4자 성어끼리)로 맞춘다. 유의어나 형태가 비슷한 단어로 구성한다.
- 빈칸 5개의 유형을 섞는다: 실사(동사·명사·형용사)의 호응, 성어, 접속어·부사(논리 관계).
- 어휘는 6급 범위 안에서 쓰고, 기출 지문을 복제하지 않는다. 새 지문을 쓴다.
- 해설과 보기 설명은 한국어로 쓰되, 중국어 표현은 인용으로만 쓴다.

### 품질 검증 (2단계)
1. **코드 검사**: 빈칸 표시 `{{1}}`~`{{5}}`가 순서대로 한 번씩 있는지, 보기 4개가 서로 다른지, 정답 번호가 범위 안인지, 보기 글자 수가 같은지 확인한다. 이어서 정답 위치가 한쪽에 몰리지 않게 보기를 섞는다(설명도 함께 재배열).
2. **블라인드 검수**: 정답을 숨긴 지문과 보기를 별도 호출에 주고 직접 풀게 한다. 동시에 "들어갈 수 있는 보기 전부"를 고르게 한다.
   - 통과 조건(1부분): 모든 빈칸에서 고른 답이 정답과 같고, 가능한 보기가 정답 하나뿐이어야 한다.
   - 통과 조건(2부분 문장 고르기): 검수자가 정답 없이 일대일로 채운 배치가 정답과 같아야 한다. 실제 시험처럼 단서와 소거로 하나로 정해지면 통과다. 앞뒤 흐름만 보고 "이것도 들어갈 수 있다"고 본 문장은 참고로만 남긴다.
3. **고치기**: 검수에 걸린 빈칸은 세트를 버리지 않는다. 검수 의견(함께 가능하다고 본 보기와 이유)을 근거로 그 빈칸의 보기만 다시 만들고, 그 빈칸만 다시 블라인드 검수한다(최대 2번).
   - 그래도 안 되면 새로 출제하고(최대 2번), 서버 제한(300초) 안에서 끝나도록 시간 예산을 둔다.
   - 2부분은 새로 쓰기(약 30초)가 고치기(약 80초)보다 빨라서, 빈칸 하나만 걸렸을 때만 고치고 나머지는 새로 쓴다(최대 3번).
   - 처음 구현처럼 통째로 버리고 다시 만들면 세 번 모두 1~2개 빈칸에서 걸려 4.7분 만에 실패했다. 고치기 방식으로 바꾼 뒤에는 출제 62초, 검수 19초, 고치기 21초, 합계 약 100초에 완성됐다.

### 풀(pool)과 지연
- 생성과 검수에 수십 초가 걸린다. 그래서 미리 만들어 둔 세트(아직 안 푼 것)를 꺼내 쓴다.
- 세트를 꺼낼 때 풀이 2개 미만이면 백그라운드로 하나를 더 채운다.
- 풀이 비었을 때만 그 자리에서 생성하고, 진행 단계("지문 쓰는 중 → 정답 검수 중")를 보여 준다.
- 신고된 세트는 `status = reported`로 바꿔 풀과 오답노트에서 뺀다.

## 3. 데이터 모델

혼자 쓰는 앱이라 문제도 사용자별로 저장한다(RLS: 본인 행만).

| 표 | 주요 열 |
| --- | --- |
| `hsk_sets` | level, part, topic, title, passage, blanks(jsonb), translation_ko, status(active/reported), origin(pool/similar), focus_words, verify(jsonb 검수 결과), model, served_at(꺼낸 시각, null이면 풀에 있음) |
| `hsk_attempts` | set_id, mode(first/retry), selected(jsonb), correct, total, duration_sec |
| `hsk_wrong` | set_id, blank_no, selected, answer, stage(0~3), due_on, review_count, resolved_at — unique(set_id, blank_no) |

- 틀린 단어는 따로 표를 두지 않고 기존 단어장 `zh_vocab`에 넣는다. 그러면 암기 상태와 복습 주기가 그대로 따라온다.

## 4. 이번 구현 범위 (MVP)

- 6급, 빈칸 채우기(part 1), 지문 1개에 빈칸 5개.
- 생성, 코드 검사, 블라인드 검수, 풀, 풀이, 채점, 해설, 보기별 설명, 지문 해석, 신고, 오답 저장, 오답노트(다시 풀기 / 비슷한 문제), 보기 단어를 단어장에 추가.

## 5. 확장

- part 2~4: `hsk_sets.part`와 `blanks` 자리에 part별 `items` 스키마를 추가하고, 풀이 화면은 part별 렌더러로 나눈다. 채점, 오답노트, 풀은 그대로 쓴다.
- 다른 급수: 급수별 지문 길이, 어휘 범위, 빈칸 수를 상수 표(`HSK_LEVEL_SPEC`)로 관리한다.
- 통계: 빈칸 유형별(호응/성어/접속어) 정답률을 보여 주고, 약한 유형을 더 많이 출제한다.
